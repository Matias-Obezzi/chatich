Automatización y Reglas

Documentación interactiva sobre el motor de automatización. El paso de web a escritorio con Tauri nos permite escalar Chatich de un simple overlay a un controlador absoluto del stream. Esta guía detalla cómo los eventos del chat (mensajes, subs, donaciones de Kick, Twitch y YouTube) pueden desencadenar acciones reales en la PC del streamer.

El modelo Trigger → Condición → Acción

Para mantener la escalabilidad y no convertir el código en una maraña de callbacks spaghetti, el núcleo del motor se diseña como una tubería unidireccional y predecible. Un evento crudo entra al bus del sistema, pasa por una serie de filtros estrictos que determinan si debe ejecutarse, y finalmente genera una tarea que se encola en el gestor de acciones del sistema operativo.

Para unificar la comunicación entre el frontend (React/TypeScript) que edita las reglas y el backend (Rust/Tauri) que las ejecuta, las entidades deben tener una representación serializable en JSON estricta y compartida. A continuación, el esquema de tipos propuesto:

export interface AutomationRule { id: string; name: string; enabled: boolean; trigger: Trigger; conditions: Condition[]; actions: Action[]; } // Los triggers nacen directamente del union StreamEvent del EventBus export type Trigger = | { type: 'chat.message' } | { type: 'sub' | 'sub.gift' | 'follow' | 'raid' | 'cheer' } | { type: 'point_redemption'; rewardId?: string }; // Los filtros evalúan el estado o payload del trigger export type Condition = | { type: 'permission'; level: 'all' | 'sub' | 'mod' | 'broadcaster' } | { type: 'min_amount'; value: number } | { type: 'cooldown'; seconds: number; perUser: boolean } | { type: 'text_match'; pattern: string; exact: boolean }; // Cada acción define parámetros fuertes; no hay comandos raw sin tipar export type Action = | { type: 'obs.scene_change'; sceneName: string } | { type: 'audio.play_sound'; filePath: string; volume: number } | { type: 'system.keypress'; keys: string[] } // ... Referirse al Catálogo de Acciones para ver la lista exhaustiva

Catálogo de Acciones

      

        Al convertir Chatich en una aplicación Tauri de escritorio, ganamos capacidades imposibles en un entorno web tradicional. Las acciones se agrupan por dominio de impacto y se catalogan según su esfuerzo de desarrollo (integración con crates de Rust o protocolos de terceros).
      

      
      

        

          
Integración con OBS Studio

          

            Cambiar escena y Toggle de fuentes Bajo
            
Vía obs-websocket v5. Se conecta al puerto local 4455. Al ser un WebSocket puro, no requiere plugins adicionales en OBS más allá del incluido de fábrica. Las promesas devuelven el ACK confirmando el cambio.

          

          

            Filtros y Grabación Bajo
            
Permite encender y apagar filtros específicos de la cámara (ej. Blanco y Negro) por X segundos y volver al estado original, o manejar el Replay Buffer para sacar clips automáticos.

          

        

        
        

          
Motor de Audio y Voz

          

            Reproductor de Sonidos Bajo
            
Usando el crate rodio en Rust para abrir y decodificar mp3/wav locales. Evita totalmente la dependencia inestable de usar un tag <audio> oculto en Chromium/Webview.

          

          

            Lectura TTS (Text-to-Speech) Medio
            
Se realiza en el backend mediante el crate tts, que mapea a la API nativa SAPI5 en Windows, o alternativamente integrando endpoints HTTP externos de ElevenLabs / OpenAI.

          

          

            Mezclador de Volumen WASAPI Alto
            
Mutear o atenuar (ducking) el volumen de Spotify a nivel sistema (System Mixer) cuando el streamer habla. Requiere interactuar con la API CoreAudio de Windows (C++ bindings).

          

        


        

          
Input y Comandos de Sistema

          

            Simulador de Teclas y Macros Medio
            
Integrando el crate enigo. Permite inyectar pulsaciones virtuales a nivel de sistema operativo. Útil para atajos globales en otros programas, mutear Discord, o presionar botones en juegos.

          

          

            Ejecución de Subprocesos (CLI) Alto
            
Invocar archivos .bat, .exe, o scripts de Python locales. Extremadamente potente pero requiere un sanitizado paranoico para evitar Command Injection mediante variables interpoladas.

          

        


        

          
Música, Hardware y Externa

          

            Controlador de Spotify Medio
            
Requests autenticados vía OAuth PKCE a la API REST de Spotify. Permite pausar, dar skip, o dejar que los viewers añadan canciones a la cola validando su duración.

          

          

            Iluminación Inteligente Medio
            
Peticiones HTTP locales al hub (Philips Hue Bridge) o controladores WLED en la misma red LAN. Se usa para cambiar el cuarto a color rojo cuando ocurre un evento crítico.

          

          

            Webhooks y Discord Bajo
            
Disparar requests HTTP POST/GET hacia el exterior. Por ejemplo, notificar automáticamente en un servidor de Discord que el stream ha comenzado o que hubo una raid gigantesca.

          

        

      

    


    
    

      
Modelo de Seguridad y Auditoría

      

        Una aplicación que posee privilegios para ejecutar macros de teclado, lanzar ejecutables o cambiar configuraciones en la máquina del streamer en respuesta a mensajes no confiables de internet es una superficie de ataque inmensa. El objetivo de Chatich no es evitar la automatización por miedo, sino blindarla por diseño. Las siguientes reglas son de cumplimiento estricto.
      

      
      

        

          
          
        

        
        

          
          
        

        
        

          
          
        

        
        

          
          
        


        

          
          
        


        

          
          
        

      

    


    
    

      
Recetas Listas y Ejemplos Concretos

      

        Para reducir la curva de aprendizaje, el motor debe incluir presets o "recetas" que cubran los casos de uso más comunes en la industria del streaming (inspirados en Lumia Stream o Streamer.bot). Aquí se exponen ejemplos de JSON que el motor parsearía.
      


      

        
        
        

          
1. Modo BRB para Moderadores

          
Un mod escribe el comando !brb (Be Right Back) en el chat y el motor cambia instantáneamente la escena de OBS y mutea el micrófono.

          

{
  "trigger": "chat.message",
  "conditions": [
    { "type": "permission", "level": "mod" },
    { "type": "text_match", "pattern": "!brb" }
  ],
  "actions": [
    { "type": "obs.scene_change", "scene": "Vuelvo Enseguida" },
    { "type": "obs.mute_source", "source": "Micrófono USB" }
  ]
}

        


        
        

          
2. Alerta de Raid Épica + Luces

          
Cuando ocurre una raid masiva (más de 50 viewers), se dispara un overlay especial, suena un audio alto y las luces físicas parpadean.

          

{
  "trigger": "raid",
  "conditions": [
    { "type": "min_amount", "value": 50 }
  ],
  "actions": [
    { "type": "overlay.alert", "theme": "raid_epic" },
    { "type": "audio.play_sound", "file": "horn.mp3" },
    { "type": "hw.hue_color", "color": "#FF0000" }
  ]
}

        


        
        

          
3. Mutear Discord temporalmente (Puntos)

          
Un usuario canjea un premio en Twitch. El motor simula el atajo global de teclado (Mute) para silenciar el chat de voz de Discord por un susto.

          

{
  "trigger": "point_redemption",
  "conditions": [
    { "type": "cooldown", "seconds": 120 }
  ],
  "actions": [
    { "type": "system.keypress", "keys": ["Ctrl", "Shift", "M"] }
  ]
}

        


        
        

          
4. Pedir Canción (Bits)

          
Un usuario dona 100 bits aportando un link de Spotify, el sistema lo valida y lo inyecta a la cola musical del streamer.

          

{
  "trigger": "cheer",
  "conditions": [
    { "type": "min_amount", "value": 100 }
  ],
  "actions": [
    { "type": "music.add_queue", "url": "$message.words[0]" }
  ]
}

        


        
        

          
5. Sustos y Jumpscares (Gift Subs)

          
Regalar una suscripción a la comunidad ejecuta un sonido estridente de forma inmediata, saltándose colas lentas y con un cooldown muy restrictivo de 5 minutos.

          

{
  "trigger": "sub.gift",
  "conditions": [
    { "type": "cooldown", "seconds": 300 }
  ],
  "actions": [
    { "type": "audio.play_sound", "file": "scream.wav", "vol": 100 }
  ]
}

        


        
        

          
6. Comando Respondedor !song

          
Cualquier viewer consulta qué tema está sonando en ese momento. Chatich lee el estado del widget musical local y envía la respuesta como chat text.

          

{
  "trigger": "chat.message",
  "conditions": [
    { "type": "text_match", "pattern": "!song" },
    { "type": "cooldown", "seconds": 15 }
  ],
  "actions": [
    { "type": "chat.reply", "text": "🎵 Suena: $current_song" }
  ]
}

        


      

    


    
    

      
Arquitectura de Ejecución Profunda (Tauri Backend)

      

        Toda la inteligencia real del motor de reglas reside exclusivamente en el binario compilado (Rust) de Tauri. El front-end en React.js, que los usuarios visualizan en la ventana principal, funciona puramente como un editor (Configurator) sin estado persistente local más allá de la UI temporal.
      

      
      

        
1. Bus de Recepción (Event Ingestion)

        

          Los adaptadores de plataforma (conexiones WebSocket hacia Kick, Twitch, y el polling hacia YouTube) inyectan structs genéricos StreamEvent hacia un canal asíncrono MPSC (Multi-Producer, Single-Consumer) manejado por tokio. Esto desacopla 100% las plataformas subyacentes del motor lógico principal, unificando la abstracción de eventos.
        

        
        
2. Motor Evaluador (Matcher Thread)

        

          Existe un hilo dedicado (Worker Thread) que consume pasivamente el canal MPSC. Ante la llegada de un evento, iterará sobre la lista de AutomationRules cargadas en el Heap de memoria. Para cada regla cuyo Trigger coincida, se evalúan secuencialmente sus Condiciones. Si la regla involucra un cooldown, el Worker consulta a una caché local concurrente (tipo DashMap). Si todas las aserciones son verdaderas (pasan), la regla madura a la etapa de ejecución y genera una tarea concreta (ActionTask).
        

        
        
3. Cola de Acciones Concurrente (Action Pool)

        

          Las acciones generadas no son inmediatas. Se despachan a un Thread Pool dedicado a I/O u operaciones de sistema (OS Blocking Operations). Sin embargo, Chatich requiere inteligencia artificial sobre concurrencia:
        

        
    
          
  • Secuencialidad garantizada: Las lecturas de TTS o audios largos no deben superponerse en cacofonía, por lo cual se encolan linealmente en un worker dedicado al sonido.
    • 
          
  • Debouncing: Múltiples comandos concurrentes para "cambiar la escena a BRB" se dediplican automáticamente a un solo request al WebSocket de OBS.
    • 
          
  • Asincronía paralela: Luces y webhooks se ejecutan masivamente en fire-and-forget, sin retrasar otras tareas críticas del UI.
    • 
        

        
        
4. IPC (Inter-Process Communication), Persistencia y Exportación

        

          Cuando el front-end requiere guardar una regla del constructor, envía un payload serializado a través de los Tauri Commands (IPC local). El backend en Rust las consolida y las escribe en un archivo seguro en el %APPDATA%/Chatich/rules.json del sistema.
        

        

          Para facilitar una comunidad de creadores, se incluye un formato de exportación donde el JSON de reglas enteras es comprimido (Zlib) y codificado en Base64 seguro para URL, proveyendo un enlace mágico como chatich://import?data=eyJuYW1lIjoi... que otros streamers pueden pegar en su cliente.
